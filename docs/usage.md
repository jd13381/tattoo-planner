# Using Tattoo Planner

The feature reference. Start and setup: [README](../README.md); development, commands and the server API: [development.md](development.md).

## Sample project

**Explore the sample** on the start screen (or on Home) opens a ready-made project with two people: Alex, a female sample body with a layout on each region (compass, moon and stars and a meander band on the left arm; sun, swallow and a lotus band on the right arm; mountains on the left calf; a fern and scales on the right leg; a mandala and waves on the torso), and Sam, a male body with a sleeve in two variants, a torso and a leg. Its images are simple placeholder motifs that the planner draws itself; none of them is real tattoo art.

The sample is **read-only**: you can move things, switch modes and look at every region and the full body, but saving, exporting and image edits are off, and the header shows **Sample (read-only)**. **Save as new project** (Settings → Project; the chip in the header leads there) copies it into a folder you choose, with the placeholder images as PNG files, and opens the copy, which you can change freely.

## Your project folder

A project is one folder (local disk, iCloud Drive, a synced folder …) that holds everything: layouts, measurements, images and exports. Create one on the start screen (name, sample body, folder) or open an existing one; the planner remembers the last project and a list of recent ones.

```
<project>/
├── project.yaml       name, body (female | male), optional height_cm, schema version
├── measurements.yaml  optional; your measurements (see Configuration)
├── layouts/           layout variants, one YAML each
├── projections/       calibrations of photos of existing tattoos
├── manifest.yaml      image catalogue, kept by the planner
├── images/            reference images
├── photos/            body photos for projections
├── edits/, generated/ Image studio results
└── exports/           PDF / PNG handouts
```

Every file is YAML or an image; the YAML files stay hand-editable and keep their comments when the planner saves them. Copy reference images into `images/` and photos of your body into `photos/`, then press **Look for new images** in the Assets tab to catalogue them.

## Image generation (bring your own key)

The Image studio's generative engine uses OpenAI's GPT Image with **your own API key**. It is optional: everything else works without it. Create a key at [platform.openai.com](https://platform.openai.com/api-keys) and add some credit under Billing. Enter it in **Settings → Image generation**, which checks it right away (valid, rejected, no access to the image model, no credit, offline): the desktop app stores it encrypted with the macOS Keychain, a planner run from git in `~/.config/tattoo-planner/openai-key` (owner-only). A key in `.env` as `TATTOO_OPENAI_API_KEY` keeps working (see [Settings for git users](development.md#settings-for-git-users)); a key entered in Settings wins over it, and `.env` is never changed. The key is only ever sent to OpenAI. At each start the planner checks the key once and says so if it stopped working (switch off in the same place). Each variant shows a rough cost (a few cents).

## Using the planner

**Navigation:** the top bar has **Layout**, **Image studio**, **Compare**, **Assets** and **Settings** (arrow keys move between them; the open tab is in the URL, e.g. `#settings/projection`; the old `#arm`, `#projection` and `#data` links open their Settings section). Settings has a side navigation with **Project** (the data folder setup), **Body & measurements**, **Projection** and **Image generation**.

- **Home:** the start tab shows the whole body you planned on a slow turntable, with the active layout variant (the starred one) on every region and a card per region; click a region to open it in the Layout tab.
- **People:** one project can hold several persons (say, you and your partner), each with an own body, measurements, layouts and photos; the image library is shared. Switch in the top bar or on Home (`docs/adr/0017-persons.md`).
- **Layout**: pick a variant from the project's `layouts/`, edit it on the 2D unwrap and see it live on the 3D arm (Reference mode by default; in blockout mode (figures dark grey, background layers light grey, bands striped, red lines red, existing tattoo outlined). Click to select, drag to move, round handle to rotate. A selected figure has eight resize handles (they light up on hover; the cursor follows the box rotation): corners resize in proportion around the opposite corner, edges stretch one side; **Shift** swaps the two, **Alt** resizes around the centre, and sizes snap to 0.5 cm (hold **Ctrl/⌘** for free sizes, at least 1 cm). While dragging, a label shows the new size ("9.9 × 18.0 cm", width × height) and a dashed outline the old one; each drag is one undo step. A figure without a width keeps it unset (it follows the height) as long as it is resized in proportion. Alt-click selects the element underneath (repeat to cycle through everything stacked at that point), and hovering outlines the shape a click would select. The 3D arm only shows the result: dragging it always rotates (right-drag pans, scroll zooms) and never selects anything; select in the 2D editor or the elements list. The side panel edits every field, grouped as Position (with the position in cm), Size, Style and Reference image, plus the layer order (**Bring forward** / **Send back**), lock, duplicate and delete. **Outer / Inner** (mode bar over the 2D editor) puts the outer or the palm-side line in the middle of the editor for pieces on the seam (Anubis, Pegasus). The variant picker, **Undo**/**Redo**, **Save as…**, **Save** and **Export** sit in the top bar on the right while the Layout tab is open. **Save** writes the YAML back, keeping comments; **Save as…** duplicates what you see into a new variant (a free name like `v1-baseline-2` is suggested; the new file keeps the comments of the one it came from, under a line saying so; the open variant stays as saved). **Save as…** opens a small form under the button: the suggested name is preselected, the hint checks it live (lowercase letters, digits and dashes, at most 64 characters, warns before overwriting an existing variant), Enter saves and Esc cancels. Every save confirms itself with a short "Saved …" message at the bottom. Switching to another variant with unsaved edits asks Save / Discard / Cancel. Unsaved edits survive a visit to another tab; the variant picker and the Layout tab show a dot and the browser asks before a reload or close discards them (the Projection tab too). Warnings show as an "N notices" chip in the top bar; click it for the list. A duplicate or invalid id shows under the id field; other errors float over the top of the workspace. The coverage table shows the share of figures, background layers, bands, lines and open skin per zone. New figures and existing tattoos start at 10 × 6 cm (unlocked), each new element a little beside the previous one. Figures without a height are drawn 10 cm tall and listed in a warning; the Anubis takes its size from `measurements.yaml` when the layout leaves it empty.
- **Body regions** (Layout tab, region picker left of the variant picker): every layout belongs to one region: left arm (the default, and every layout without a `region:` key), right arm, left leg, right leg or torso (`docs/adr/0011-bodies-and-regions.md`). The variant picker lists the chosen region's layouts; a region without one opens an empty layout (`torso-1`, …) that becomes a file on the first **Save** (with `region: torso` after its name). The editor's centre buttons, edge labels and cm readouts use the region's lines (legs: front/lateral/back/medial from the shin; torso: right flank/front/left flank/back, centred on Front or Back), the coverage table its zones (leg: shin, calf, knee, thigh front and back; torso: chest, stomach, upper and lower back, flanks), and the export its wording. Regions nobody measured use the sample body (`male` unless `measurements.yaml` says `body: female`), scaled by `height_cm` when given; an unmeasured right arm or leg copies the measured other side. The elbow pose is for arms only. Existing tattoos can be projected from photos onto every region.
- **Full body** (Layout tab, switch over the 3D view): the whole sample body in a relaxed A-pose with every region textured by its last opened (else its active, starred) layout in the current mode, regions without one in plain skin, and head, neck, hands, feet, hips and shoulders as neutral shapes. **Front / Back / Left / Right** set the camera; click a region to edit it.
- **Elements list** (Layout tab, top of the right column): every element of the variant, top layer first, with its category colour, a warning dot (hover for the reason: height not set, no or unknown reference image, projection problem) and a lock toggle. Click a row to select the element; drag a row to change the layer order.
- **Undo and shortcuts** (Layout tab): **Undo**/**Redo** (arrow buttons next to Save as…, or Cmd+Z / Shift+Cmd+Z, Ctrl on Windows and Linux) step back through every edit: a whole drag, a typing burst in one field and a run of arrow-key nudges count as one step each. Loading or saving a variant starts the history afresh. Further keys: Cmd+S saves (also while typing), Cmd+D duplicates, Delete or Backspace deletes the selected element (not when locked), Esc deselects or leaves Draw mode, the arrow keys nudge the selected element by 0.5 cm (Shift: 2 cm) on the skin, `]` and `[` move it one layer up or down, **V** picks the select tool and **R** toggles the Line tool, and `?` (or the **?** button at the bottom of the tool rail) lists them all. They only act while the Layout tab is open and focus is not in a text field.
- **Layout workspace:** the tool rail on the left holds Select (V), the add buttons (figure, existing, band: each adds one in the middle of the editor), **Background layers** (opens the Background view, see [Background layers](#background-layers)) and the Line tool (R); hover a tool for its name. The bar over the 2D editor switches the mode, the grid and the centred side; the status bar under it shows u/v and the position in cm under the cursor (else of the selection), the zoom and **Fit**. Over the 3D view float the view bar (Front/Back/Medial/Lateral, Screenshot), the elbow pose and the coverage table; the right column has **Elements**, **Layers** and **Assets** as tabs and the inspector of the selected element (or of the variant).
- **Line tool** (Layout tab, tool rail, R): while it is on, a colour picker (any colour, plus red, black, grey and blue swatches) floats over the 3D arm, and dragging on the arm draws a stroke on the skin (rotation is off; right-drag pans, scroll zooms; works on the bent arm too). Each stroke becomes a new `line` element (`red-stroke-2`, `red-stroke-3`, … in red, `stroke-1`, … in another colour, stored as `#rrggbb`; blockout draws every line red), as wide as the layout's first red line, else 1.5 cm), selected and editable like any line in the 2D editor, and saved to the YAML with **Save**. The stroke is simplified to the fewest points that stay within 0.3 cm of what was drawn (also across the inner seam); clicks without a stroke are ignored. With a line selected, **continue <id>** extends that line instead, at its nearer end; its existing points are kept as they are.
- **Modes** (bar over the 2D editor; `?debug` in the URL adds the texture render time): **Reference** (default) draws the same layout with the reference images (PROJECT_BRIEF.md §10.1 F6): figures and existing tattoos show their asset's cut-out inside their box, multiplied onto the skin so white paper and pale skin vanish; background layers lie under every motif (see [Background layers](#background-layers)); bands are the procedural patterns below, clipped exactly to their shape (also across the inner seam); red lines lie on top of everything (§4.3); **Blockout** as above (with **Grid** on it also covers the old "cm grid" mode). A figure whose image is missing shows a labelled placeholder box with the reason (no asset, not in the manifest, file missing, no data folder, cannot be shown). Images are decoded once per page load and cached, so switching modes is instant.
- **Change image** (Layout tab): the element panel of a figure or existing tattoo shows its image large, with **Change image** (a large picker panel next to the button, sized to the window: search, kind filter and the grid; click an image to assign it, Enter takes the first hit, Esc closes). A selected figure also shows a floating **Change image** button beside it in the 2D editor. Each change is one undo step.
- **Assets** panel (Layout tab, right column): thumbnails of every `manifest.yaml` entry (hidden ones left out), filterable by kind and tag, with a search over id, notes, source and file. Select a figure or existing tattoo in the editor, then click an image to assign it (`asset:`). Missing files are greyed out, manifest problems are listed as warnings. **Reload** catalogues images newly copied into the project folder (the same as **Look for new images** in the Assets tab), then re-reads the manifest and the images. The element panel shows the assigned image with its cut-out marked and edits the reference fields below.
- **Export** (top bar, Layout tab): one click writes the handout for the tattoo artist and PNGs of every picture into the project folder (see [Export for the artist](#export-for-the-artist)). With unsaved edits it reads **Save & export** and saves first. Progress and the result (where it was saved, **Open PDF**, or the error) show in a card at the bottom of the window. Disabled, with the reason as tooltip, while there are layout errors or images still loading, and without a project folder (or in the read-only sample).
- **Compare**: two variants side by side on the 3D arm, read-only (edit in the Layout tab). A full-bleed workspace: the two arms stand next to each other at a seam in the middle, each with its coverage table floating at its outer edge. Along the top float **Blockout / Reference** (left), the **A** and **B** pickers with ⇄ (swap) on the seam, and the four views (right); both arms share the camera, so rotating or zooming either one moves both. Every coverage cell that differs from the other variant by at least 2 points is tinted (red = more, blue = less; the tooltip gives the difference). The inspector column on the right sums it up ("3 elements differ", open skin of the whole arm A → B with the change in points; click the line to jump to the element list), shows the descriptions (once when both share it), the elbow pose, and the elements that exist in only one variant, whose values differ (by id, with the changed fields) or that are identical. An invalid variant file shows its error over its arm; in Reference mode a "Loading images…" chip shows while images load. While the Layout tab has unsaved edits, they can be compared too ("(unsaved edits)", with a dot on the picker, preselected against the saved file). Variants are the files in the project's `layouts/`; make one with **Save as…** (with a single variant and no unsaved edits the tab says so and offers **Open Layout**).
- **Assets** (tab, ADR 0020): a sidebar with **All images**, the shared library (**Ideas**, **Made in studio**, **Backgrounds**), the current person's **Measuring photos** and **Tattoo photos**, and the smart albums **Unused**, **Missing files** and **Hidden**. Sections come from the folders, kinds and projections; **Move to …** fixes one for good (`category:` / `person:` in `manifest.yaml`). Click an image for its details: where it is used (layout elements with **Show**, projections, edits), tags and notes, **Hide** / **Unhide**, **Move to …** and **Move to Trash**. **Select** (or Cmd/Ctrl-click, Shift-click) picks several images for the action bar; Cmd/Ctrl+A selects all, Delete moves to the Trash, H hides, Cmd/Ctrl+Z undoes, Esc steps back. A deleted image can be restored from the toast for 8 seconds; then it goes to the system Trash (elsewhere `<project>/.trash/`). Drop image files on the page to add them to the open section. The line on top condenses the folder status with **Look for new images**, **Check folder** and a link to Settings → Project. The sample project is read-only.
- **Settings → Body & measurements** (was the Arm tab): pick the **sample body** (female or male) and optionally your **body height** (every value nobody measured is scaled to it; in a project folder both are written to `project.yaml`, in an older data folder to `measurements.yaml`), then a **region** (left/right arm, left/right leg, torso). The region fills the view in 3D with a 1 cm grid (bold every 5 cm, red centre lines; legend bottom left; view bar with the four fixed views and the screenshot camera top left; the elbow pose for arms). The form on the right lists the region's values by section (lengths, circumferences, positions, and the torso's shape ratios): an empty field shows the value in use as its hint (the sample body's, or the other side's for a limb), an entered value overrides it, ↺ resets a field to that value, and each row says whether it is **measured**, **edited** (unsaved, with the file's old value) or from the **sample** / **other side**. Every edit shows at once in every 3D view (Layout, Compare, full body). **Save** writes them into `measurements.yaml` per region under `regions:` (the left arm stays in the old top-level `lengths` / `circumferences` / `positions` blocks when the file uses them), keeping comments and untouched lines as they are; **Discard** drops them. The Settings tab and the section show a dot while there are unsaved values.
- **Measure yourself** (Settings → Body & measurements, optional): a guided wizard for the chosen region, one value per step: body height first, then lengths and circumferences in measuring order, each with a short instruction (where the tape goes, which landmark, relaxed or not) and a schematic with the tape line highlighted. The 3D region follows every value as it is typed. **Next** keeps the value, **Skip** leaves it as it was, **Back** goes back, **Close** (or Esc) returns to the form at any step (entered values stay as unsaved edits); the summary lists what is your own and what keeps the sample's value, and saves. The torso's shoulder line and cross-section shape cannot be taped and are left to the form. The arm steps follow [measuring.md](measuring.md).
- **Elbow pose** (every 3D view: Arm, Layout, Compare): **Straight**, **Bent 90°** or the slider (0–120°) flexes the elbow; the forearm swings towards the palm side, the skin bends over about ±6 cm around the elbow tip, stretching a little on the outer side and creasing on the inner side. The texture and the unwrap stay the same, so it shows how the elbow and skull area deform. The pose is shared by all tabs; the medial and lateral views show the bend best. Exports still show the straight arm. Model and limits: `docs/adr/0005-elbow-bend.md`. **Screenshot** (the camera icon in the view bar on the Layout and Arm tabs; the top-right corner of the Projection tab's 3D view) saves a PNG to the browser's download folder. The open tab is kept in the URL (`#compare`), and the chip at the right of the header says whether the data folder is set (click it for Settings → Project).
- **Settings → Projection** (existing tattoos, `docs/adr/0024-projection-workspace.md`): a list of the existing tattoos brought onto the body from photos, each with its first photo, body part, state ("Ready · 5 photos", "2 of 5 photos missing") and the layouts that show it. **Add existing tattoo** opens the workspace with a setup sheet first, **Edit** opens it with the tattoo's answers, **Advanced** the full calibration page (below), **Delete…** (also in the workspace and on Advanced) moves the tattoo's projection file to the Trash after a confirmation: its photos stay in Assets, and a ticked "Also remove it from the layouts that show it" takes it out of those layouts (otherwise they show "projection … not found" until you remove it there). Not in the read-only sample. **Setup sheet**: name, body part (all five regions) and photos. The picker lists your tattoo and measuring photos with their edits from the Image studio stacked on them ("Photo", "Edit 1", …), then the other images; picking an edit keeps the photo as the frame the points are placed in and uses the edit's pixels (`cleaned:`). **Look for new images** catalogues new files in the project folder. **Start** (or **Done** when reopened from the bar) opens the workspace, Esc cancels. **Workspace**: the photos on the left (a filmstrip with a status dot per photo, **×** removes one, **Add photo** reopens the sheet), the photo in the middle with the tools **Outline** (1: drag four dots onto the left and right edge), **Distances** (2: drag two points onto spots whose distance from the wrist crease, ankle or navel you know and type the cm, or click a landmark chip such as Elbow tip, values from your measurements, sample values in italic), **Camera** (3: where the camera was, as in ADR 0023, with the twisted option under Advanced) and **Clean up** (4). The toolbar over the photo also turns it (↺ ↻; the start of the body part, e.g. the wrist, belongs at the bottom), shows a cm **Ruler** along the outline and, for a photo that uses an edit, **Photo / Both / Edit**. Dots can be focused (Tab) and moved with the arrow keys (Shift for bigger steps). Next to it the 3D body part over the unwrap follow every change as soon as a photo has its outline and distances. On the unwrap, drag the current photo sideways to turn it round the body part, up or down to move it along, and its top and bottom handles to stretch it (arrow keys: 0.1 cm, Shift 1 cm); **Ghosts** (**G**) shows the other photos' outlines. The inspector on the right has the photo's checklist (click an item to open its tool), the tool's settings and the **Area**: automatic by default (all photos plus 1 cm, dashed on the unwrap and in 3D), **Hold area** keeps it as it is, **Fit to photos** makes it automatic again; a saved area that no longer holds every photo switches to automatic when opened, with a note. **Clean up** (`docs/adr/0023-projection-cleanup.md`) paints on the whole canvas: **Ink only | Photo** switches the picture (hold Space to compare), **Keep only the ink** (on for a new tattoo) evens out the skin's light and shadow and keeps only the ink, with **Strength**, the shadow size in cm and **Keep the ink's colour**; **Remove small specks** drops dots and short grey streaks that touch no other ink (up to the size in mm²). What is left can be painted away with the **Eraser** (**E**), or brought back with **Restore** (**R**, also for specks); **[** and **]** change the brush size (in cm, the circle shows it), **Clear erasing** removes all strokes, **+** / **−**, pinch or Ctrl + wheel zoom, **0** fits, and the right or middle mouse button + drag moves the picture; **Show erased** shows removed ink in faint pink. The strokes are kept in the projection file (`erase:`), the photos stay as they are, and the 3D view, blockout and export use the cleaned result. **Picture used for this photo** picks the photo itself or one of its edits; **Edit in Image studio** opens the photo there (the built-in **Tattoo ink only** or the GPT preset of the same name), and after **Save & close** and **Back to the projection** the workspace comes back as it was with the new edit picked. An edit of another shape gets **Fit to the photo's frame** (stretched, fitted inside or cut to fill) and arrow buttons that nudge it until **Both** lines up (`cleaned_offset`). The workspace's bar holds the name, **Undo** / **Redo** (⌘Z, ⌘⇧Z or ⌘Y; one step per drag, Esc during a drag cancels it), **Cancel** (asks first only with unsaved changes) and **Save** (⌘S); the small menu beside Save picks the layout the tattoo is shown in and lists what is still open, errors first (a missing name or points that cannot be right block saving; an untouched outline, distances or camera side is only listed). Save writes the projection plus a locked existing element in that layout (by default one that already shows it, else the one open in the Layout tab, else the first, else a new `<region>-1`) and says which; a layout with unsaved edits in the Layout tab is left alone (the message says so).
- **Advanced** (Settings → Projection → Advanced, the former Projection tab): every number of a calibration, e.g. Jan's Anubis built from all five photos (`anubis1_nr.JPG`, `anubis_extra1–3.JPG`, `anubis_extra4.png`; see [jans-sleeve.md](jans-sleeve.md)). A full-bleed workspace like the Layout tab: the photo editor fills the left, with the photo switcher floating on top and a status bar below it (grid colour key, photo size and turn; hover it for the full how-to). The middle column shows the 3D body part (view buttons and screenshot on top, elbow pose at the bottom) over the combined patch. The inspector on the right holds **This photo**, **Patch (all photos)** (hover a label for what it means) and **Share of the patch** (each photo's share and weight; click a row to open that photo). **‹ Existing tattoos** (or Esc; asks first with unsaved edits), the projection picker, **Revert** and **Save** sit in the page's own bar above the workspace; the picker and the section show a dot while there are unsaved edits, and patch warnings show as a notices chip there. **Save** (or ⌘S / Ctrl+S) writes the YAML and confirms with "Saved …"; **Revert** drops the edits. Without a data folder, or while a photo is missing or loading, its frame says why and its fields are disabled.
- **Image studio** (mode _Edit_): touch up a reference image without leaving the planner. Measuring and tattoo photos are listed under **Body photos** (hidden images are not), so a photo can be cleaned up here and used for a projection. The tab is a full-bleed workspace: the image browser on the left (search by id, notes or source, filter by kind and tag; **Reload** also picks up images newly copied into `refs/`, `cards/`, `existing/` or `arm-photos/`), the canvas in the middle, and the inspector on the right. Pick an image (the canvas shows it large with a "Versions of …" row of its saved edits), choose an engine and run a step; the first step opens an **editing session** (`docs/adr/0010-editing-sessions.md`). A version strip v0 → v1 → … sits above the canvas; the last version (outlined) is where the next step starts, and the button names it (e.g. "Apply Line art to v1").
  - **Built-in** (default, no key, no network; `docs/adr/0013-builtin-image-operations.md`): remove background (flood fill from the border with a colour tolerance and a soft edge, for scans and drawings on a plain background), tattoo ink only (for a photo of a tattoo: evens out the skin's light and shadow and keeps the ink on a transparent background, black and grey or in colour; ADR 0023), line art (threshold with smoothing), levels / contrast (black and white point), black and grey, invert, rotate (90° left or right, 180°) and mirror. The canvas previews the chosen operation live while you move its sliders; **Apply** runs it on the full image and adds the result as the next version at once. **Undo** drops the last version again.
  - **Generative** (GPT Image, redraws): for changes that need new pixels, such as fewer snakes, a skull moved or detached, a hand removed and the area behind it filled in. Presets: simplify, remove an object, tattoo ink only, remove text / watermark. The dev server sends a copy of the image and your instruction (German is fine) to OpenAI (`gpt-image-2.5-sunburst`, about a minute) and shows 1–3 variants, each with a rough cost, next to the version they came from; click one to see it large, before and after side by side (← / → step, Esc back). **Continue with this** makes a result the next version; **Try again** reruns the prompt. A generative result is redrawn and may change details you did not mention, so compare before and after. GPT Image answers in three shapes only, so the planner pads the image to the closest one with plain bars and crops them off the answer: the result keeps the original's proportions. Needs your own OpenAI API key (see [Image generation](#image-generation-bring-your-own-key)): in the desktop app entered in Settings → Image generation, from git in `.env` as `TATTOO_OPENAI_API_KEY`. Without a key the Generative engine shows this setup step and stays off; the built-in operations keep working. Design and limits: `docs/adr/0008-generative-edits.md`.
  - **Versions and saving:** engines mix freely within a session (e.g. fewer snakes with GPT Image, then remove the background built-in). Click an earlier version in the strip to see its other results, **Continue from vK** or **Save vK**. **Save & close** writes the last version as `edits/<original>-edit-N.png` with a manifest entry (`derived_from: <original>`, tag `edited`, each step with its engine in `notes`, `From <id>.` when it was an edit of an edit), ends the session and picks the new file, ready for the next round. **Close** ends a session without saving (it asks first). Sessions survive tab switches and page reloads, not a restart of the planner. To try a version on the arm, **Save vK** keeps it as an image without closing the session; assign it in the Layout tab, then come back and carry on. **Dark / Light** switches the checkerboard behind the images (dark by default; light shows black line work on transparent backgrounds). The original is never changed. Without a project folder the tab only links to Settings → Project; in the sample project it is off (read-only).
  - **Reference images** (GPT Image only): the **+** in the corner of an image on the left (shown on hover) sends it along, up to four, numbered in the order they are sent and listed in the inspector, e.g. "Mache ein rotes Dreieck drumherum wie in diesem Referenzbild". The prompt names each reference by its id and notes.
  - **Background** (mode switch at the top of the inspector): a seamless tile for [background layers](#background-layers). Pick a preset (clouds, stars, smoke, waves, geometric, shadow) or describe it, name it, and create with GPT Image. Tiles are always square, opaque and black and grey on white; the server fixes the seam of every result (offset-and-blend) and the canvas shows each result tiled 3 × 3, so a seam or a repeating blob shows at once. **Save & close** writes `backgrounds/<name>-N.png` with a manifest entry (kind `background`, tag `background`); the Layers panel lists these first. Images copied into a project's `backgrounds/` are catalogued as the same kind.
  - **Create new** (mode switch at the top of the inspector): describe a new motif or pattern (until there is a first version, the canvas shows an empty artboard in the chosen format), optionally click up to four images on the left as references, pick a name, format (square, tall, wide) and background (transparent by default), click **New image** and then **Create with GPT Image** (1–3 variants). From v1 on the session works like any edit (built-in or GPT Image); **Save & close** writes `generated/<name>-N.png` and a manifest entry (kind `idea`, tag `generated`, prompts and references in `notes`). Design: `docs/adr/0009-create-images.md`.
- **Settings → Image generation**: whether an OpenAI key is set for the Image studio, how to set one up, and a link to [privacy.md](privacy.md).
- **Settings → Project**: the open project's name, body and height (saved in `project.yaml`), its folder (**Show in Finder** in the desktop app), **Open other project…** and **Close project**; for the sample **Save as new project**, for an older data folder **Move into project**. Below, the folder's files per sub-folder in collapsible tables, the expected structure and which features need which folder; **Check again** re-reads it.

Geometry and unwrap conventions: `docs/adr/0002-arm-geometry-and-unwrap.md`, generalised to every body region in `docs/adr/0011-bodies-and-regions.md`.

**Patterns** for `pattern:` in a layout (drawn in reference mode, `src/render/patterns/`; sizes are real cm on the skin):

| Name                     | Kind       | Look                                                                                       |
| ------------------------ | ---------- | ------------------------------------------------------------------------------------------ |
| `snake-scales`           | background | overlapping scale rows (≈ 1.2 cm); `density` scatters them out into open skin              |
| `hatching`               | background | diagonal engraving lines; `density` tightens the spacing and adds cross-hatching above 0.5 |
| `starfield`              | background | sparse dots and small four-point stars                                                     |
| `meander`                | band       | Greek key spirals between two border lines, module ≈ band height                           |
| `lotus` (`lotus-frieze`) | band       | lotus flowers alternating with papyrus umbels, linked by garland arcs                      |

Bands fit a whole number of repeats around the arm, so they meet at the inner seam. Line patterns of background layers are seeded from the layer `id`: the same layout always looks the same. Any other name draws a faint diagonal placeholder hatch.

## Background layers

Patterns and backgrounds lie **under** the motifs as an ordered list of layers, like layers in an image editor (`docs/adr/0019-background-layers.md`). A motif on top covers the background: figures and existing tattoos knock it out along their image (or their box when there is no image), bands along their strip, with `gap_cm` of bare skin around them. It is a sketch aid: it shows how an arm looks when the motifs are tied together by a background, not a design.

- **Layers tab** (right column of the Layout tab, or the **Background layers** tool in the rail): the layers, top first, each with an eye (show/hide), lock and drag to reorder. **+** adds one: a **standard background** (clouds, stars, smoke / shading dotwork, waves, geometric lattice, wind bars), a **line pattern** (snake scales, hatching, starfield) or an **image from the project** (tileable images of kind `background` first). New layers cover the whole region with a 0.3 cm gap.
- **Background view** (**Motifs | Background** over the 2D editor; opening the Layers tab switches to it): the motifs are dimmed and cannot be picked; the inspector edits the selected layer: source (pattern or image, tile size or scale in cm, rotation, offset, density, ink), opacity, blend (multiply, or normal to cover), gap, and **Whole region / Area**. An area is the union of shapes drawn with **Rect** (M), **Ellipse** (E) and **Polygon** (P; click the corners, Enter or a click on the first corner closes, Esc cancels), refined with the **Brush** (B) and **Eraser** (X) at a radius in cm, with a soft **Feather** in cm. **Select** (V) moves a shape; Delete removes it. Shapes wrap across the inner seam like everything else.
- **Motifs** switch over the 3D view: off shows the background alone (in 2D and 3D), on shows it combined with the motifs.
- Tiles are cm-true and repeat without a seam around the limb; blockout shows layers in the light grey the fillers had; coverage counts them as **Background** (their hard edge, gap and feather left out); the handout lists them before the elements.
- **Standard backgrounds** are drawn procedurally (deterministic, black and grey) until `assets/backgrounds/` holds a generated image for them: `npm run backgrounds:generate` sends the fixed prompts of `assets/backgrounds/backgrounds.yaml` to GPT Image (your `TATTOO_OPENAI_API_KEY`, one paid request per image; `-- clouds stars` for some, `-- --force` to replace), makes each result seamless, keeps it at most 1024 px and 2 MB and fills in `file`, `generated` and `licence` in the catalogue. These PNGs are the one kind of image committed to git.

In the YAML (`backgrounds:` comes before `elements:`, bottom layer first):

```yaml
backgrounds:
  - id: stars
    source: { standard: stars } # or { pattern: snake-scales, density: 0.3 } or { image: night-sky-1, tile_cm: 10 }
    opacity: 0.8
    cover: area # default: region (the whole body part)
    shapes:
      - { kind: ellipse, u: 0.5, v: 0.75, w_cm: 12, h_cm: 9 }
      - { kind: span, u: [0.36, 0.64], v: [0.6, 0.9] } # the old filler region
    feather_cm: 1.5
    gap_cm: 0.3
```

**Fillers became background layers.** A layout with `type: filler` elements still opens: each one is read as an area layer with its region as a `span` shape (a notice says so), and the file keeps the old form until you save the variant, which writes the new one.

## Export for the artist

**Export** in the top bar (Layout tab) renders the saved layout and writes, only into the project folder:

```
<project>/exports/
├── v1-baseline-2026-11-03.pdf      the handout
└── v1-baseline-2026-11-03/         PNGs: {front,back,medial,lateral,unwrap}-{blockout,reference}.png
```

A second export of the same layout on the same day gets `-2`, then `-3`; nothing is ever overwritten. A card at the bottom of the window shows the progress and, when done, the file name and an **Open PDF** link (served read-only by `GET /api/exports/<base>.pdf`); about 15–20 s. If it fails, the card shows the error, naming the step that failed.

The PDF (A4, English): a cover with the layout's name as title, its description as subtitle, the date, the note that this is a sketch and the artist has creative freedom, and a legend of the element types; all four views (front = inner, back = outer, medial, lateral) at a glance with blockout and reference side by side; one page per view with the elements facing that side; the unwrap with cm grid in both modes; a table of every element (type, reference image, size in cm, position, style or pattern, `notes:` from the YAML); coverage per zone; what this layout leaves open (unset heights, missing images, placeholder measurements). All handout wording lives in `src/export/strings.ts`, ready for a German version. Give an element a `notes: "…"` line in the YAML to pass a remark to the artist.

The endpoint behind it (`server/exportsApi.ts`): `GET /api/exports` (enabled or why not), `GET /api/exports/<path>` (read a written file back), `POST /api/exports` (reserve a name), `PUT /api/exports/<base>.pdf` or `/<base>/<name>.png` (write one file; type, signature, size and path are checked; nothing outside `exports/`). Decisions: `docs/adr/0004-export.md`.

## Reference fields in a layout

Figures and existing tattoos take these optional fields (rules in `src/layout/imageFit.ts`):

| Field                | Meaning                                                                                                                                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `crop`               | `{ x, y, w, h }`, 0–1 from the left/top edge of the image as stored (before turning). Overrides the asset's `crop` in the manifest; without either, the whole image.                                                                        |
| `image_rotation_deg` | `90`, `180` or `270`: turns the cut-out clockwise, e.g. for a photo of the arm lying sideways.                                                                                                                                              |
| `flip`               | `true` mirrors the image left-right (after turning).                                                                                                                                                                                        |
| `feather_cm`         | soft edge of the cut-out in cm, default `1`; `0` for a hard edge.                                                                                                                                                                           |
| `filter`             | `none`, `grayscale` or `hatching` (grayscale with an engraving line screen). Default: `grayscale` when the element's centre is on the forearm, `none` above the elbow. Photos are stretched so skin turns white.                            |
| `projection`         | existing tattoos only: a calibration in the project's `projections/` (e.g. `anubis`). The tattoo is then drawn from all its photos where they put it, and the fields above, `position` and `size_cm` only apply while that cannot be built. |

Size: when `size_cm.w` is not set, the box takes the proportions of the upright cut-out (in every mode, so blockout, metrics and picture agree; until the image has loaded, or without a data folder, the old 0.55 × height is used). When both `h` and `w` are set, the image is fitted inside the box without distortion and centred.

## Configuration files

All of these live in the project folder (for an older data folder not yet moved: in this repo's `config/`).

- `project.yaml`: `version: 1`, `name`, `body: female | male` (the sample body), optional `height_cm`, optional `active:` (the starred variant per region) and `persons:` (further people, data in `persons/<id>/`; `docs/adr/0017-persons.md`); edited in Settings → Project, unknown keys are kept. Body and height here win over the same keys in `measurements.yaml`.
- `measurements.yaml`: measurements in cm (PROJECT_BRIEF.md §13.1). The top-level `arm: left` blocks are the left arm; optional `body` and `height_cm` (the place before `project.yaml`; used only where `project.yaml` says nothing) and `regions:` with any subset of a region's keys (`src/body/inputs.ts` lists them). `null` or a missing key means not measured yet; a project without the file uses the sample body. How to measure and photograph the arm: [measuring.md](measuring.md).
- `layouts/*.yaml`: layout variants (§13.2), e.g. `v1-baseline.yaml`; a new project starts with an empty `first-sketch.yaml`. Hand-editable.
- `projections/*.yaml`: how photos of an existing tattoo map onto a body region (ADR 0006, ADR 0014; `region:` defaults to `arm-left`), written by the projection workspace, fine-tuned in Advanced or by hand. Optional (ADR 0023): `cleanup: { flatten_cm, strength, keep_color }` (ink only) and, per photo, `cleaned: <file>`, an edited version whose pixels are used instead of the photo's, with `cleaned_fit` and `cleaned_offset: { x, y }` (ADR 0024) to line up one of another shape.
